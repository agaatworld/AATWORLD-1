## 2. How the page is built and tested

```
cd /home/user/AATWORLD-1/_work/site-v3
node tools/build.js                       # data/data.js + page.html + index.html (safe to run at the same time as other builders)
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8790/index.html || (python3 -m http.server 8790 &)   # only if nothing answers
node tools/check.js --routes exhibitions --langs ar,en --sizes 1920x950,1366x768,1100x900,390x844
node tools/shot.js exhibitions 1920x950 ar                 # → shots/exhibitions-ar-1920x950.png, then LOOK at it (Read the PNG)
node tools/shot.js exhibitions-ae 390x844 en --full
node tools/shot.js home 390x844 ar --click ".mast-secs"    # click something first (sheet, menu, a chip…)
node tools/shot.js club 1366x768 ar --scroll "#club-join"  # scroll to a selector or a pixel offset
node --check js/pages/exhibitions.js
```

- `index.html` is the publish skeleton around `page.html` and is the file you test. `?lang=en` (or `zh-TW`, `zh-CN`, `ms`) picks the language: `index.html?lang=en#exhibitions-ae`.
- **Always run `node tools/build.js` after editing.** The browser loads the inlined `index.html`, not your source file.
- `tools/check.js` writes `tools/check-report.json` and prints one line per case. Every case must say `OK`. It checks: page errors, text < 16 px, sideways scroll, elements out of the window, broken pictures, contrast < 4.5 (< 3 for large text), `section.band` without a visible `<h2>`, an empty `#view`, loose Latin text and number ranges in RTL, `af.png`, two neighbouring bands of the same colour, the PC menu (one row or 4+4), and placeholder words. It also lists 16–16.9 px text as `s16`; with `--verbose` it shows each item. Only app names, tab labels, trade-line labels on phones and counter sub-lines on phones may be 16 px.
- The final artifact is ONE fragment, `page.html`: `<title>`, metas, the Google Fonts links, ONE `<style>` and ONE `<script>`, plus the `img/` files. `build.js` enforces this, so never add `<script>`/`<style>` tags in your markup strings that you expect to run.

## 3. The module interface

Copy `js/pages/pages.js`. Every module file is a plain ES2017 IIFE that registers itself while loading:

```js
(function () {
  'use strict';
  var AAT = window.AAT, D = AAT.data, ui = AAT.ui, esc = AAT.esc;
  var t = function (k, v) { return AAT.t('exhibitions.' + k, v); };

  AAT.strings.exhibitions = {            // only UI copy that is NOT in data.json (DESIGN.md §8)
    ar: { search: 'ابحث باسم المعرض أو المدينة' },
    en: { search: 'Search by show name or city' }
  };

  AAT.acts['ex-field'] = function (el, ev, ctx) { /* a chip with data-act="ex-field" was clicked */ };

  AAT.pages.exhibitions = {
    render: function (ctx) { /* return the HTML string for #view, or null → the app shows the 404 page */ },
    mount: function (ctx, view) { /* optional: after insertion (observers, timers, listeners on view) */ },
    unmount: function () { /* optional: before another module renders (disconnect observers, clear timers) */ },
    update: function (ctx, view) { /* optional: same module, new hash: return true when you updated in place */ },
    title: function (ctx) { /* optional: document.title text (default: the H1 text) + " · AAT" */ },
    chrome: function (ctx) { /* optional: return false to hide ribbon/masthead/menu/tab bar/contact band/footer (reader) */ },
    contactBand: function (ctx) { /* optional: return false to leave out the floor contact band */ },
    init: function () { /* optional: once at boot */ },
    onRoute: function (ctx) { /* optional: after every route render, in any module (assistant uses it) */ },
    onLang: function (code) { /* optional: after a language switch (then the route re-renders) */ }
  };
}());
```

The **ctx** that every hook receives:

| Field | Example for `#exhibitions-ae-food-and-beverage` |
|---|---|
| `hash` | `'exhibitions-ae-food-and-beverage'` (canonical, without `#`) |
| `head` | `'exhibitions'` (the token before the first `-`, lower case) |
| `rest` | `'ae-food-and-beverage'` (everything after the first `-`) |
| `id` | `null` (a number when `rest` is all digits: `#company-18` → `18`) |
| `parts` | `['ae','food','and','beverage']` (`rest` split on `-`; join it again where ids contain dashes) |
| `module`, `nav` | `'exhibitions'`, `'exhibitions'` (which menu item is current) |
| `lang`, `o`, `rtl` | `'ar'`, `'ar'`, `true` |
| `prev` | the previous ctx (or null) |

Rules for modules:
- `render` returns a string. Build it from `AAT.ui` components and your own prefixed markup, and escape **every** data string (`AAT.esc`, `AAT.txt`, `AAT.Lh`, `AAT.lt`). Never use `innerHTML` with unescaped data.
- When an item does not exist (`#company-999`, `#exhibition-nope`), return `null` and the app shows the 404 page.
- Events go through **one delegated handler**. Put `data-act="<prefix>-<verb>"` on a button (or on a `<form>` for submit) and register `AAT.acts['<prefix>-<verb>'] = function (el, ev, ctx) {}`. Clicks and submits call `preventDefault()` for you. Name actions with your prefix (`ex-`, `hm-`, `cl-`, …). The core actions are `lang`, `globe`, `sheet`, `sheet-close`, `assistant` (optional `data-q`), `ask` (a `<form>` with an input named `q`, or `data-q`), `copy` (`data-copy`, `data-target`, `data-ok`), `copy-num`, `go` (`data-href`) and `toast` (`data-msg`).
- Inputs that react while typing (`input`/`change`) are bound in `mount(ctx, view)` on `view` and released in `unmount`.
- Navigation is a plain `<a href="#route">`. For a filter or a page turn that should not re-render, use `AAT.setHash('exhibitions-ae')`: it calls `replaceState` and does no render. `AAT.go('#x')` navigates and re-renders even when the hash is already current.
- Never use `alert`, `confirm`, `prompt`, `window.print`, iframes, `fetch`, script-started downloads, or external pictures. Fullscreen may start only from a click, and you must handle its rejection. A form never claims that something was sent.
- `localStorage` only inside try/catch and only for conveniences, under the key prefix `aat3.` (the language is `aat3.lang`).

## 4. The AAT API (js/app.js)

### 4.1 Data
- `AAT.data`: the whole `data.json` (schema in `data/README.md`).
- Lookups (each returns `null` when the item is missing): `AAT.company(id)`, `AAT.product(companyId, k)` → `{c, p}`, `AAT.show(id)`, `AAT.article(id)`, `AAT.newsItem(id)`, `AAT.modernItem(n)`, `AAT.field(id)`, `AAT.country(cc)`, `AAT.cat(key)`.
- `AAT.origin(company)` → `{cc, country, en, ar, text}`. `cc` is the flag country code, or `null` (India has no shipped flag). `text` is the city line in the visitor's language.
- `AAT.LINE`: the 14 country codes with shows, in trade-line order Taiwan → Algeria. Afghanistan and Yemen are never in it.
- `AAT.stats`: `{shows:1464, showCountries:14, companies:35, logos:29, products:127, prodCos:28, pictured:53, modern:40, modernGroups:6, articlesFresh:13, articles:37, news:26, members:2831, issue:560, pages:100, shipped:12, years:45, since:1982}`, all computed from the data.
- `AAT.modernArName(item)` gives the Arabic name of a modern item (the text before the first Latin letter). `AAT.byLine(article)` gives "بقلم …" or "By …". `AAT.issueLine()` gives "العدد 560 · أكتوبر 2026". `AAT.showCity(show)` gives the city as HTML.

### 4.2 Language and text
- `AAT.lang` is one of `'ar' | 'en' | 'zh-TW' | 'zh-CN' | 'ms'` (default `ar`; `?lang=` for tests; stored in `localStorage['aat3.lang']`). `AAT.rtl` is true for Arabic. `AAT.o` is `'ar'` or `'en'`: use it for ar/en-only fields, e.g. `about.paragraphs[AAT.o]`. `AAT.dir` is `'rtl'` or `'ltr'`. `AAT.langs` lists the five languages in menu order. `AAT.setLang(code)` switches language without a reload.
- `AAT.t(key, vars)` returns a UI string.
  - `'exhibitions.search'` → `AAT.strings.exhibitions[lang].search`, falling back to English, then Arabic.
  - `'mb_read'` (no dot) → `data.i18n[lang].mb_read`, falling back to English, then Arabic.
  - `{n}`-style placeholders are filled: `AAT.t('mb_read', {n: 560})` → "اقرأ العدد 560".
  - A missing key prints a console warning and returns the key itself. `check.js` will show it.
- `AAT.L(v)` gives content in the visitor's language. `v` is `{ar,en,…}` or a string. Arabic falls back to English; English falls back to Arabic; zh/ms use `v[lang]`, then the `data.tx` translation of `v.en`, then English. It returns plain text. `AAT.Lh(v)` is the same as HTML with direction isolation.
- Escaping and isolation (DESIGN.md §7):
  - `AAT.esc(s)` escapes text and attribute values.
  - `AAT.lt(s)` → `<bdi dir="ltr" class="lt">s</bdi>` for an inline Latin name, phone, e-mail or range.
  - `AAT.ltb(s, tag='span', cls)` → an LTR **block** (`dir="ltr" class="ltb"`), for Latin names that wrap or clamp. It is right-aligned on the Arabic site.
  - `AAT.rtlb(s, tag, cls)` → an Arabic block inside an LTR page (`dir="rtl" lang="ar"`).
  - `AAT.arx(s)` → an Arabic sentence with every Latin run, e-mail, URL and number range isolated ("مزايا AAT Tube", "(TiTE)", "11–13").
  - `AAT.txt(s)` → the safe default for any text: on the Arabic site it applies `arx` when needed; on LTR sites it puts Arabic text in an RTL bdi.
  - `AAT.ui.blockText(s, tag, cls)` → a block whose direction follows its script.

### 4.3 Numbers, counted nouns, dates
- `AAT.num(1464)` → `"1,464"`. Use Western digits everywhere.
- `AAT.count(n, key)` → `"1,464 معرضاً"` / `"1,464 shows"`. It follows the Arabic counted-noun rule of §8.3. `AAT.count(n, key, true)` gives the noun only. The keys are `show, intl, company, advertiser, product, member, article, news, page, country, year, issue, field, name, language`. Add your own from your module: `AAT.nouns.booth = {ar:['جناح','أجنحة','جناحاً'], en:['booth','booths']}`. `AAT.arForm(n, [one, few, many])` gives the raw form.
- `AAT.monthName(3)` → "مارس" / "March". `AAT.fmtMonth('2027-03')` → "مارس 2027". `AAT.fmtDate('2027-03-02')` → "2 مارس 2027".
- `AAT.fmtRange(start, end, approx)` returns **HTML** in which the day range is LTR-isolated: "2–7 مارس 2027", "28 فبراير – 2 مارس 2027", or the month only when `approx`. `AAT.fmtRangeText(...)` gives the same as plain text, for attributes.
- `AAT.pagesLabel([18,19])` → `"18–19"`. For `[2,11]` it gives `"2"`, the first page.

### 4.4 Pictures (prototype policy)
- `AAT.img(path, {alt, w, h, cls, eager, ratio, style})` returns an `<img>` string, or `''` when `path` is null **or not shipped**. When it returns `''`, render **no picture box**. Every image gets `width`/`height` or `aspect-ratio`, `loading="lazy"` (unless `eager`) and `decoding="async"`.
- `AAT.src(path)` returns the path when it is shipped, else `''`. `AAT.pageImg(n)` and `AAT.thumb(n)` return the magazine page or thumbnail path for pages 1–12 and `''` beyond. `build.js` writes the list of shipped files to `window.AAT_FILES`, so nothing outside `img/` can be shown.
- Never write `img/flags/af.png` and never show a country with 0 shows.

### 4.5 Router and helpers
- `AAT.ROUTES` (head → module), `AAT.parse(hash)` → ctx, `AAT.route` (the current ctx), `AAT.go(hash)`, `AAT.setHash(hash)`, `AAT.render(ctx?, {full, keepScroll, noFocus})` (normally only the router calls it).
- Old routes are rewritten: `#exhibition` → `#exhibitions`, `#club-join` → `#club`, `#calendar` → `#exhibitions`, `#membership` → `#club`. An unknown head goes to `#home`, and the address is replaced with the canonical hash.
- Each render sets `document.title` to `"<H1 text> · AAT"`, scrolls to the top, focuses the H1 (no focus box), marks the current menu, tab and sheet item, and fills `#contact-slot`.
- Other helpers: `AAT.toast(msg, ms)`; `AAT.copy(text, okMsg, nodeToSelect)`, which uses the clipboard in the click handler and on rejection selects the text and says so; `AAT.openAssistant(query)`; `AAT.icon(name, size)` (names: `globe phone chat search menu close book cal box mail pin arrow back check copy ext pdf full zoom plus minus home users building news grid`; `arrow` and `back` flip in RTL); `AAT.$`; `AAT.$$`; `AAT.debounce`; `AAT.uid`; `AAT.closeOverlays()`.

## 5. Section, band and opening-board pattern

1. Every page starts with `ui.openingBoard(...)` (navy). Each page has its H1, brass figure and picture side in DESIGN.md §4.4. There is **no breadcrumb** and **no small label above the H1**.
2. Then the bands alternate: **paper → floor → (at most one navy feature band) → paper → floor …**. Two neighbours never share a colour. `check.js` reports `bands=` when they do.
3. The app appends the **floor contact band** and the **navy footer**. So your last band must be **paper or navy**, not floor, unless your module returns `contactBand:false`.
4. Every band is `ui.section({...})`: one H2 with the red bar, an optional meta line with a count, at most ONE action at the inline end, then the content. There is no kicker, no "see all" link and no duplicate title. Only a lone text block under a short board may use `untitled:true`.
5. Content widths come from `.wrap`, which already includes the safe-area gutters. Never add horizontal padding shorthands to full-width bands. A full-bleed strip (such as the conveyor) goes outside `.wrap` in your own markup; use `.bleed` for its gutters.
6. A sticky deck under the PC menu uses `top: var(--sticky-top)`, which is the safe-area inset plus the 64 px menu bar. On phones it is the 76 px logo row.

Shared classes you can use in your markup (all defined in `css/site.css`): `wrap bleed band b-paper b-floor b-night shead h2 h3 meta muted lead stack grid g-2 g-3 g-4 g-auto g-dir cols prose board board-pad board-red card card-body rows row row-t facts tbl frame cap stamp pstamp pgno ds tag chip chips qchip btn btn-red btn-navy btn-line btn-ghost btn-s btn-block btnrow field label inp sbox cf cf-t lt ltb rtb clamp1 clamp2 clamp3 sr empty more apps app cnts cnt figs icard cover-board spread seal tl lc pc mc ac hl srow dboard bigph mail weblink addr`. Do **not** restyle them from your file; add your own prefixed class beside them instead (`class="pc ex-pc"`).

## 7. RTL and languages (DESIGN.md §7)

- Arabic is the default (`<html lang="ar" dir="rtl">`). English, zh-TW, zh-CN and ms are LTR with the English layout and must be complete. Content without English is shown in Arabic RTL blocks with a factual English label. It is never hidden silently and never machine-translated.
- **Logical CSS only**: `margin-inline-*`, `padding-inline-*`, `inset-inline-*`, `border-inline-*`, `text-align: start|end`. The only physical sides allowed are for the floating chat button and the assistant panel, which sit physically on the left.
